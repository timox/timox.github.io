Vue d'ensemble
Principes du modèle V3
  • Hiérarchie stratégique : Programme → Stratégie → Mission → Mise en œuvre → Tâche
  • Source unique : Toute la hiérarchie dans Ssir_strategie2
  • Classification 3 axes : Chaque tâche classifiée selon 3 dimensions orthogonales
  • Liaison directe : strategie_id lie la tâche à sa Mission
Avantages
  • Mise en œuvre pour regrouper les tâches
  • Une seule source de vérité
  • Structure hiérarchique claire
  • Analyses multidimensionnelles via les 3 axes
Niveau intermédiaire : Mise en œuvre

Une Mise en œuvre regroupe plusieurs tâches au sein d'une Mission. Elle permet d'organiser le travail en phases ou lots cohérents.

  • mise_en_oeuvre_code - Code unique (ex: MEO-001)
  • mise_en_oeuvre_nom - Nom descriptif
  • categorie - MCO, Projet ou Imprévisible
  • mise_en_oeuvre_charge_estimee - Charge prévue (jours)
  • mise_en_oeuvre_charge_reelle - Charge réelle (jours)
  • Préfixe [MEO] - pour les tâches support

Taxonomie V3 - Les 3 Axes

Chaque tâche peut être classifiée selon 3 dimensions orthogonales et indépendantes. Ces axes permettent des analyses croisées et des vues multidimensionnelles.

Exemples d'utilisation
Exemple 1 : Incident (non planifié)
titre: "Serveur mail down"
strategie_id: null (pas de mission)
nature_activite: INC
genre_action: COR
etape_cycle: ETP.EXP
previsibilite: Imprévisible
Exemple 2 : Tâche rattachée à une Mission
titre: "Configurer tenant M365"
strategie_id: → Migration M365
nature_activite: PRJ
genre_action: CFG
etape_cycle: ETP.REA
previsibilite: Prévisible
Comment rattacher une tâche à une Mission ?
  1. Identifier la Mission dans Ssir_strategie2 (champ action)
  2. Noter l'id de cette ligne
  3. Renseigner strategie_id de la tâche avec cet id
  4. La tâche hérite automatiquement du Programme et de la Stratégie
